# Maintaining the template

Install this source repository with:

```powershell
dotnet new install D:\CRM-Build
dotnet new dataverse-starter -n XYZ.Sales -o D:\repos\XYZ.Sales
```

Use a namespace-safe name such as XYZ.Sales. The sourceName token Company.Crm
renames projects, namespaces, solution, Sparkle paths, scripts and generator settings.
Solution and project GUIDs are regenerated by the template engine.

The default output has no Account business example, generated environment metadata,
PAC-generated runtime, signing key, connection settings or build artifacts.
The source repository keeps its existing generated files; they are excluded from output.
Use --include-account-example to include Account plugins, application code and their tests.
The example includes a minimal OOTB Account model, overwritten by npm run model:generate in a real project.

Inside the generated solution:

```powershell
npm run setup
npm run check
```

setup creates a unique signing key and runs pac plugin init for the new namespace.
It does not authenticate, read CRM metadata, register plugins or deploy anything.
runtime:generate records the hash of the original generator output after creation.
Re-running setup retains an existing key and regenerates the runtime.

After template changes, instantiate under a different name into a fresh directory.
Check that no source prefix, customer metadata or local artifacts leaked into output.
Run setup and check there, including the merged artifact tests.
Also instantiate with --include-account-example and verify the example is included.

The template is installed from its source directory. Keep that directory available;
install again after changing template configuration. No global installation is needed
for smoke tests: use a separate dotnet template hive.

Reference: https://learn.microsoft.com/en-us/dotnet/core/tools/custom-templates

Run powershell.exe -NoProfile -File scripts/TestTemplate.ps1 to repeat template verification.
The script preserves results under artifacts/template-tests, uses no CRM credentials and never deploys.
It fully builds/tests both the default output and the optional Account variant without CRM credentials.
